Fortran mutates its arguments; JAX cannot. Every `INTENT(OUT)` and
`INTENT(INOUT)` argument therefore comes back as a return value, which is
why the signature looks the way it does. Do not add, remove, reorder or
rename a parameter.

## Rules

1. Return a new value. Never mutate an argument. For an indexed write, use
   `x.at[i].set(v)` / `.add(v)`, which returns a new array.
2. A loop whose iterations are independent becomes a whole-array `jnp`
   expression, not a Python `for`.
3. A loop that carries a dependency is a recurrence: use `jax.lax.scan`.
   A vectorised expression would compute a different answer, silently.
4. A data-dependent branch becomes `jnp.where`, not `if` — an `if` on a
   traced value fails under `jit`.
5. **Guard the untaken branch.** `jnp.where(x > 0, sqrt(x), 0.0)` evaluates
   `sqrt(x)` for negative `x` too, so the gradient is NaN even though the
   forward value is fine. Make the unsafe branch safe first:
   `sqrt(jnp.where(x > 0, x, 1.0))`.
6. Keep the declared array rank and index order. The caller relies on the
   Fortran layout.
7. No `print`, no file I/O, no global state.
8. Preserve the numerical formulation exactly — same operations, same
   order where it affects rounding. This is a translation, not a
   reimplementation.
